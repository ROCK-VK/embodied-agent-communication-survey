# 本地模拟环境

配置日期：2026-10-04。本地模拟环境的公开说明；日志不上传。

## 实际安装

| 环境 | 位置或运行方式 | 版本 |
|---|---|---|
| 数据实验 | 项目根目录 `.venv-data`，Windows x86-64 | Python 3.13.9；NumPy 2.5.3、Pandas 3.0.6、Matplotlib 3.11.2、scikit-learn 1.9.1 |
| A2A | 项目根目录 `.venv-a2a`，Windows x86-64 | Python 3.13.9；官方 a2a-sdk 1.2.1；完整依赖见锁定清单 |
| ROS 1 | Docker 容器 `embodied-sim-ros1` | Ubuntu 20.04.6、Noetic、Python 3.8.10、catkin 0.8.12 |
| 编译工具 | ROS 容器内 | GNU 9.4.0、CMake 3.16.3、Git 2.25.1、pip/venv、rosdep、rosbag |

ROS 基础镜像是官方 `ros:noetic-ros-base-focal`，Dockerfile 固定其 SHA256 摘要。SDK 当前源码使用 protobuf 与 `a2a.server.routes`，不要套用旧版 `a2a.server.apps` / Pydantic 类型示例。

Windows 与 ROS 容器采用独立 Python 解释器；数据训练和 ROS 节点先通过文件及独立进程交互，不共用 site-packages。虚拟环境复用已有 Windows Python，不改 Anaconda 包或全局 PATH。ROS 2 扩展现已安装：Ubuntu22.04.5 / Humble / Python3.10.12 / rclpy3.3.22 / rmw_fastrtps_cpp6.2.10；专用 embodied-sim-ros2，域47且只回环，镜像摘要固定在compose中。

## 隔离与存储

- 项目文件放在克隆目录；Docker 数据沿用使用者现有配置，不迁移引擎。
- 不对现有 Ubuntu 执行安装、升级、配置修改；不改现有两个容器的文件、挂载和配置。
- 容器只有本项目的只读挂载 `/project`；Linux 构建目录使用专用卷 `embodied-sim-local_catkin-workspace`，位于 `/workspaces/catkin_ws`。
- ROS 容器限制为 2 CPU、2 GiB 内存、256 PID；专用内部网络，不向 Windows 发布端口，不使用特权或宿主机网络，不自动重启。
- 镜像构建时需要联网，运行容器的内部网络不提供外网；以后新增系统依赖通过修改 Dockerfile 并重建本项目镜像处理。
- 无全局清理、Docker 重启或 WSL 全局停止操作。仍共享宿主机资源，不能保证同时运行时毫无性能影响。

两个 Python 环境约 419 MB，项目下载缓存约 100 MB；ROS 扩展镜像报告逻辑大小约 2.97 GB（十进制，包含共享基础层），不是独占磁盘新增量。实际物理占用还包括 Docker 缓存、虚拟磁盘增长与专用卷，不能把镜像大小直接当作新增占用。

## 运行与停止

在 PowerShell 中进入项目根目录后，直接调用虚拟环境解释器，不需要激活，也不需要修改系统执行策略：

```powershell
.\.venv-data\Scripts\python.exe 环境/check_data.py
.\.venv-a2a\Scripts\python.exe 环境/check_a2a.py
docker compose -f 环境/compose.yaml up -d --no-build ros1
docker compose -f 环境/compose.yaml exec ros1 bash
```

进入 ROS 容器后，每次新 shell 显式加载 ROS：

```bash
source /opt/ros/noetic/setup.bash
cd /workspaces/catkin_ws
catkin_make -j2 -l2
source devel/setup.bash
roscore
```

结束本项目工作时只停止专用容器，保留工作区：

```powershell
docker compose -f 环境/compose.yaml stop ros1 ros2
```

完整环境验收：`& .\环境\验证环境.ps1`。恢复依赖与镜像：`& .\环境\恢复环境.ps1`，使用 Python 3.13，并要求 Docker 启动。若本机脚本执行策略阻止 `.ps1`，使用上面的单条命令，不修改全局执行策略。

## 验收范围

- 数据环境：依赖检查、合成数据生成、轻量分类模型拟合、CSV 写出及 PNG 绘图通过。
- A2A 环境：依赖检查、官方 protobuf 类型序列化、官方 Agent Card HTTP 路由返回 200，通过进程内 ASGI 验证；该项只描述环境验收；后续已完成真实HTTP任务、SSE状态、结构化结果和取消，见阶段报告。
- ROS 环境：空 catkin 工作区构建、启动私有 roscore、单容器内 TCPROS 发布/接收实际消息通过。验收脚本退出时关闭测试 master，不长期占用 11311。
- rosdep 命令可用；外部依赖解析缓存未专门验收，后续新增 ROS 包时按需处理。
- 后续已完成360次数据选择实验、ROS1五场景与接收数据离线训练、A2A真实HTTP/SSE任务/状态/产物/取消，以及ROS2同契约和QoS对照；见根目录阶段报告。仍未做真实无线、机器狗/Jetson实测。这是x86-64本地模拟，不推断Orin NX性能。

验收结果位于 `验收产物/`；完整依赖分别见 `requirements-data.lock.txt`、`requirements-a2a.lock.txt`。当前公开环境清单见 `environment-public.json`。锁定 Python 依赖与 ROS 基础摘要；Dockerfile 的额外 Ubuntu apt 包未固定版本，当前已构建镜像 ID 和实际包清单另行记录。

安装依据：[官方 ROS 镜像](https://hub.docker.com/_/ros)、[官方 A2A Python SDK](https://github.com/a2aproject/a2a-python)。
