# 实际模块接口与统计口径

版本：2026-10-04。实际使用的消息契约与本轮源码一致；没有接入机器狗 SDK 或实际传感器。

## 数据选择实验

| 模块 | 输入 | 输出 | 约束 |
|---|---|---|---|
| 合成感知源 | seed、场景、8维特征分布 | 1500 条感知 JSON；独立 1000 条测试集 | 70% 概率沿用前一观测并加小噪声，训练与测试独立 |
| 感知预测 | 独立 240 条预训练样本得到的分类器 | prediction/confidence | 测试集不训练预测器；sensor_shift 场景故意制造坐标失配 |
| 数据选择 | features、prediction、confidence、消息大小 | 每 100 条窗口中的可发送序号 | 不读取真实标签；25%/50%/100% 字节预算 |
| 模拟标注 | 选中 seq 与单独标签表 | 接收端训练标签 | uint32 seq+uint8 label，假设每条额外 5 字节，所有策略均计入预算；不是标签获取算法 |
| 训练评估 | 选中消息的四位小数特征及模拟标签 | accuracy、macro F1、test log loss、耗时 | 固定 50 次更新与 50ms 墙钟计算预算分开；不使用测试集调参 |

消息字段：`seq`（整数）、`collected_at`（秒）、`source`（来源字符串）、`features`（8维数字数组）、`prediction`（预测类别）、`confidence`（概率）、`payload_bytes`（当前紧凑 JSON UTF8 字节数）。真实标签不在候选消息内。payload_bytes 自身也参与序列化，迭代求得一致大小后断言核对。

数据实验预算 = 紧凑 JSON 字节 + 模拟标注的 5 字节。线上 TCP/IP、连接握手、其他协议头未计量。JSON/prediction 生成是所有策略共同预处理；感知预测耗时计入计算预算，数据生成和 JSON 序列化未计入。模型拟合、测试评估的计时范围分别说明，不把测试计算算进训练时限。

## ROS1 真实消息链路

| 实际节点/进程 | 接口 | 类型 | 机制 |
|---|---|---|---|
| perception_source | 发布 `/demo/perception` | std_msgs/String，data 中为上述 JSON | 实际 60Hz；采集时间改用本容器 monotonic 秒 |
| selector | 订阅 perception、发布 `/demo/selected` | std_msgs/String | 每15条窗口；按低置信度优先排序以演示启发式选择；半预算或全预算 |
| receiver | 订阅 selected | std_msgs/String | ROS 订阅队列与有界业务队列分开；业务满时丢最旧，处理后按 TTL 判断 |
| 各节点 | 发布 `/demo/events` | std_msgs/String 事件 JSON | seq、事件类型、节点、monotonic 时间与可选大小/年龄字段 |
| logger | 订阅 events/perception | std_msgs/String | 保存逐条事件；源间隔超过350ms且源未结束时记录断流 |
| offline trainer | 读取 received.jsonl | 文件接口 | 从合成标签表取标签，在独立 Windows 进程训练；不阻塞 ROS 回调 |

演示用 String+JSON 减少消息生成依赖，不代表最终设备接口选型；后续正式集成可以把契约变成自定义 `.msg`。来源时间与年龄基于同一容器单调时钟，不能跨设备直接相减。

ROS1 字节预算 = 4字节 String 长度 + UTF8 JSON 字节；没有实际发送标注消息，因此不沿用数据实验的5字节标注项。两类实验目的不同，不将字节值直接混合比较。selector 的累计“选中”字节在注入丢弃前扣预算，注入丢弃是故障演示，不回补发送窗口。

事件守恒校验：source_sent = selector_received；selected = forwarded ∪ injected_loss；forwarded = receiver_arrival；receiver_arrival = accepted ∪ queue_drop ∪ stale_drop ∪ shutdown_drop。每类同时检查序号集合，不能只看总数相同。预算筛除与接收缺失单独计数，当前没有无法解释的接收缺失。

## ROS2 对照

source、selector、receiver 是三个 rclpy 节点，由同一进程 executor 调度；ROS1 是四个独立进程，不据此比较速度。topic 为 `/comparison/perception`、`/comparison/selected`，沿用 JSON 与4字节长度的公共应用预算，实际 CDR 序列化大小另记。时间保留数据源的合成值，不测 TTL。对照得到与 ROS1 正常场景相同的42个序号。

QoS 正常流：RELIABLE / VOLATILE / depth200。专项检查 RELIABLE→RELIABLE、BEST_EFFORT→BEST_EFFORT、BEST_EFFORT→RELIABLE，第三种接收不兼容事件并收到零消息。独立 ROS_DOMAIN_ID=47 与 localhost-only，未建立 ros1_bridge。

## A2A 任务接口

| 接口 | 输入与输出 | 实测范围 |
|---|---|---|
| GET `/.well-known/agent-card.json` | 官方 SDK AgentCard | 技能 summary、JSONRPC 接口、协议1.0、streaming能力 |
| POST `/rpc`，SendMessage | text Part 内 JSON：records、delay_ms；返回 Task+artifact | 20条感知结果摘要；包括预测类别计数和平均置信度 |
| GetTask | id → 已完成 Task | 查询内存任务状态 |
| SendStreamingMessage | 同任务输入 → SSE | working、artifact、completed实际收到 |
| CancelTask | id → canceled Task | 人工设2.5s任务等待后取消 |
| 错误处理 | UnknownMethod / 不存在的Task ID | 返回标准 RPC 错误对象 |

A2A服务只绑定127.0.0.1，运行后关闭临时端口。业务 Part.data 显式转成 protobuf Value。输出 prediction_counts 是预测统计，不是假定真实类别；服务规则不证明某种数据策略最优。
