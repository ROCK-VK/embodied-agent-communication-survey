**项目：** 基于多模态机器狗的通感算控一体化平台搭建

**状态：** 本阶段的本地调研与模拟交付已完成，包括360次数据实验、ROS1五场景、A2A网络任务演示、网络调研和ROS2扩展对照；最终结果与边界见[阶段报告](阶段报告.md)。本计划结合学长反馈，先使用合理的软件与数据假设开展电脑模拟。假设不等于实验室实测配置，全部结果应按实际运行环境标注。

## 1. 工作目标与模拟基线

重点研究“感知结果数据流中哪些数据值得传递”：在给定通信预算和计算预算下，对比数据选择策略的开销和学习效果。同时补充 ROS 1/ROS 2 接口区别，以及 A2A 高层任务协作的适用性。

| 项目 | 本轮采用的基线 | 依据与证据级别 |
|---|---|---|
| 设备背景 | NVIDIA Jetson Orin NX 开发平台 | 学长称其为 Orin NX Developer Kit；准确模组容量、载板和镜像未实测 |
| 参考软件组合 | JetPack 5.x / Ubuntu 20.04 / ROS 1 Noetic | 结合 Orin NX 与“ROS 1 更多”的反馈选取兼容组合，作为工作假设；不宣称统计上概率最高或设备正在使用此版本 |
| ROS 2 对照 | Ubuntu 22.04 / ROS 2 Humble | 参考既有宇树 ROS 2 资料，在独立环境中进行补充验证 |
| 实际执行平台 | Windows 独立 Python 虚拟环境 + Docker Desktop/WSL 2 的 x86-64 ROS 容器 | 电脑模拟逻辑数据流，不模拟 Orin NX 的 ARM/GPU 硬件性能 |
| 单机数据流 | 感知结果产生 → 选择/发送 → 接收缓存 → 训练/评估 | 为学长描述的研究问题构造的教学模型；所有模块先运行于同一电脑 |
| 数据与模型 | 带真值的合成特征流，接收端训练小型分类模型 | 可控地比较策略；不冒充机器狗真实感知数据或论文复现 |
| A2A 用途 | 高层请求分析任务、反馈任务状态、返回结构化结果 | 独立于 ROS 传感消息流；先做规则型服务，不要求大模型 API |

## 2. 环境安装与验收顺序

已在本目录配置 Windows 数据与 A2A 独立虚拟环境，并在专用 Docker 容器中配置 Ubuntu 20.04.6 / ROS Noetic；不修改现有 Ubuntu 26.04 或其他项目。数据训练/绘图、SDK 类型与 Agent Card 路由、ROS 单容器发布订阅最小验收通过。实际版本与使用方式见 [环境说明](环境/环境说明.md)。以下保留原安装顺序作为背景，当前实际方式以环境说明为准。

1. **准备 ROS 1 环境。** 保留现有 Ubuntu 26.04，已采用独立 Ubuntu20.04/Noetic Docker 容器，不新增或修改现有 WSL 发行版。先核对架构、系统版本、空间、DNS 和软件源访问。
2. **安装基础依赖。** 在实验 Linux 中准备 Git、编译工具、CMake、curl、Python、pip/venv；记录包版本。代码与构建工作区放在 Linux 文件系统，避免 Windows 路径与权限差异。
3. **安装 Noetic 最小通信组件。** 首选 ros-base、rospy、roscpp、消息生成工具、catkin、rosdep 和 rosbag；先验证 roscore、发布/订阅与消息类型查询。软件源及依赖失败要保存原因，不无限重试源码编译。
4. **准备数据实验环境。** 使用独立 Python 虚拟环境安装 NumPy、Pandas、Matplotlib、scikit-learn；按选定 Python 版本安装兼容版本并记录依赖。纯 Python 实验与 rospy 节点先采用独立进程，避免不同 Python/依赖环境混用。
5. **准备 A2A 环境。** 在单独虚拟环境中使用满足官方 SDK 要求的 Python，安装官方 A2A SDK 及示例必要依赖，固定 SDK/协议版本；只绑定本机地址，完成客户端—服务端交互。
6. **ROS 2 对照已完成。** 使用独立Ubuntu22.04/Humble官方Docker镜像，验证rclpy消息流与QoS兼容，不修改ROS1环境。分别使用独立终端加载 ROS 1/2，首轮不安装 ros1_bridge。

Humble 的 Ubuntu 二进制安装说明见[官方文档源码](https://github.com/ros2/ros2_documentation/blob/humble/source/Installation/Ubuntu-Install-Debs.rst)。电脑上不安装 Jetson 的 ARM 镜像或 JetPack 固件；本轮不需要 CUDA、TensorRT 或三维机器人仿真器。

**环境验收产出：** 实际 OS/架构、Python/ROS/SDK 版本清单；最小发布订阅记录；依赖锁定文件及复现步骤。若 Noetic 安装受阻，先在可用 Python 环境完成数据实验与 A2A 调研，并准确记录 ROS 部分未完成。

## 4. 感知结果与数据选择实验设计

### 4.1 数据流和候选消息

链路：**模拟感知结果 → 数据选择模块 → 受预算限制的发送 → 接收缓存 → 分类训练 → 统计记录**。

先生成带类别真值的合成特征数据，包含重复样本、噪声和不同类别分布，以模拟感知结果的冗余与质量差异。模型先选小型逻辑回归或浅层神经网络，具体选择与超参数记录在配置中。

消息草案包含 seq、采集时间、来源标识、特征向量、感知预测类别/置信度和载荷大小。分类真值单独保存在实验数据集中，不用于发送端的价值排序；若训练需要标注，用一致的模拟标注流程提供，并记录是否计入传输预算。预测类别不直接当作真值。

### 4.2 策略和公平对照

| 策略 | 用途 | 拟比较内容 |
|---|---|---|
| 全量发送 | 未限发送的参考，可能超预算；非最优上界 | 全量处理成本及学习结果，不作为同预算公平基线 |
| 固定间隔抽样 | 简单低开销基线 | 在给定预算内保留样本 |
| 随机抽样 | 同预算对照 | 防止将数据排序造成的偏差误认为策略优势 |
| 价值筛选 | 候选启发式方案 | 分别观察置信度、变化/新颖性或不确定性；不预称“最优” |

在相同训练数据流、字节预算、模型与评估条件下比较预算内策略；优先取保留比例 25%、50%、100% 作初始参数扫描，再按实际消息字节换算预算。每个窗口有明确的可发送字节上限，不能只按条数称为带宽相同。

发送端计入特征计算、价值打分与选择耗时，接收端计入缓存处理与训练耗时；选得更少不自动等于计算成本更低。比较“相同训练更新步数”和“受相同计算预算限制”的结果时分别报告，不混用结论。

使用固定生成配置及种子，建议至少 3 个种子；训练和测试独立，测试集不参与筛选、拟合、阈值选择或超参数调整。时间序列实验按时间段划分，避免重复观测跨训练/测试泄漏。真实结果可以是无提升或下降，不预设筛选必然有益。

### 4.3 指标与结论边界

- 通信：候选/发送/接收/主动丢弃条数、序列化载荷字节、时间窗口与发送预算违约；线上完整包量需实际抓包，载荷估算不得写成全部网络开销。
- 计算：选择耗时、训练耗时、更新次数、CPU/内存、样本数；本机耗时不当作 Orin NX 实测。
- 数据：样本年龄、重复率、类别覆盖、丢弃原因；不能用“高置信度”直接等价“训练价值高”。
- 学习效果：独立测试集准确率、宏平均 F1、训练损失；分别记录模型、训练步数、随机种子和预算。

**拟交付结论形式：** 在指定合成数据、模型与预算下，某策略降低或增加了哪些成本，测试指标如何变化。结果属于教学模拟，不证明学长论文算法最优，也不证明真实机器狗训练效果。

## 5. ROS 通信与网络机制验证

拟建 ROS 1 节点：perception_source 发布 /demo/perception，selector 发布 /demo/selected，receiver 接收缓存，logger 记录事件；训练程序可读取保存的数据独立执行，避免长训练阻塞订阅回调。

## 6. A2A 调研与最小演示

阅读[官方文档与示例](https://a2a-protocol.org/latest/)，记录实际查阅的协议/SDK 版本，解释 Agent Card、能力发现、消息、任务状态、结果和协议绑定。将 A2A、ROS 1、ROS 2/DDS、TCP/UDP/IP 放到对应职责位置，避免把 A2A 当成 IP 网络层协议。

本机演示拟采用“分析请求方 → 数据摘要服务”：请求分析一段合成感知数据，服务按规则返回类别统计和候选策略摘要。先复用官方最小示例，不需要大模型密钥；检查能力声明、请求、结果，以及示例支持的任务状态/反馈。若所选示例仅返回同步消息，不能据此声称验证了长任务反馈或取消。

分别报告 A2A 消息结构与任务协作语义、ROS 数据流机制；A2A 不预设代替高频感知消息传递，也不预设能自动选择有价值数据。性能测量仅限实际运行的路径，不以两类不同负载的演示得出协议快慢排名。
