# 机器狗上行感知数据的 Wi-Fi CSI 采集与时空关联方案

方案摘要｜更新日期：2026-10-10

## 方案摘要

本方案面向机器狗上传视觉或激光雷达相关数据时的无线信道测量，目标是把每条感知样本、其采集时刻与机器狗位置，同实际无线传输期间接收端记录的 CSI 关联起来。

实施上先核验实验室现有无线设备及数据路径，再用兼容的 Atheros CSI 节点完成小流量基线测试；链路有效后，以带业务样本标识的受控 UDP 数据验证“业务包—CSI”关联，随后确认机器狗数据确实经过被测 Wi-Fi 链路，再逐步接入真实感知数据和位姿。优先使用实验室已有且确认兼容的设备；若没有，再讨论外接 CSI 节点或其他采集平台，不预设刷写设备或改动 Jetson。

预期形成的关联记录为：感知样本标识、传感器类型与时间、位置来源及坐标、对应的无线包信息、CSI 时间与矩阵。一个感知样本可能对应多条 CSI 记录，关联以样本标识和实际载荷证据为主，时间戳用于辅助校验。

当前已完成资料调研和方案设计；实验室无线设备型号、固件、数据路径及定位来源尚未确认，未安装 CSI 驱动、未刷写设备、未采集真实 CSI。下阶段先完成设备与方案核验，再按下文的实验顺序推进。

## 目标与测量边界

- 记录感知数据上传期间接收端测得的 Wi-Fi CSI，并与产生该数据的时刻及位置建立可复核的关联。
- 明确所测的是哪一段无线链路、由哪一端发射和接收，以及 CSI 记录对应哪些实际传输帧。
- 区分承载业务数据的无线帧 CSI 与独立探测帧 CSI。首选验证实际业务帧；若先用探测帧验证链路，结果应标为同时段信道参考，不能当作业务帧自身 CSI。
- CSI 表示接收端对无线信道的测量，不会自动携带 ROS 样本编号或机器人坐标。样本与位置需要从上层消息、定位数据和传输载荷中取得。
- 外接无线节点测到的是该节点与对端之间的无线链路。若目标是机器狗现有无线网卡的 CSI，必须确认该网卡、驱动和采集工具兼容；外接节点方案不能替代对原生无线链路的测量。

## 候选链路与设备方案

首选验证路径是实验室现有的兼容设备。学长提供的 Atheros CSI Tool 可作为候选方案，其项目资料针对特定 Atheros/Qualcomm Atheros、ath9k 系列硬件；兼容性需按芯片、设备完整型号、硬件版本、驱动和工具版本逐项确认。项目描述的标准 AP–Client 采集要求发送端和接收端使用兼容实现，发送端发出可供接收端测量的 HT sounding 帧。

候选数据路径如下：

传感器或感知结果 → Jetson → CSI-TX 节点 →（Wi-Fi 被测链路）→ CSI-RX 节点 → PC/服务器

- CSI-TX 与 CSI-RX 之间的测量链路必须经过 Wi-Fi 空口。
- 电脑至路由器的网线用于设备管理；Jetson 至 TX、RX 至服务器的有线连接属于候选业务路径，需配置并验证路由或桥接。
- 若业务数据由 Jetson 经以太网送入外置 TX 节点，再从该节点经 Wi-Fi 发出，实验测量的是外置 TX 至 RX 的无线链路。
- 如实验室设备不兼容，不直接刷写或更换固件；先记录型号与限制，再确认可用的兼容设备、替代平台及批准的操作方式。

| 角色 | 需要确认的内容 | 作用 |
|---|---|---|
| TX / 发射端 | 完整型号、硬件版本、无线芯片、驱动、CSI 工具版本、实际出口接口 | 发出测量帧或承载业务数据的帧 |
| RX / 接收端 | 完整型号、硬件版本、无线芯片、驱动、CSI 工具版本及采集输出 | 接收无线帧并记录 CSI 与可用的包信息 |
| Jetson / 机器狗侧 | 无线设备、ROS/业务数据出口、上行路径及接口 | 提供感知数据、样本标识和位姿 |
| PC / 服务器 | 接收地址、接口、时钟来源及数据保存位置 | 接收业务数据并整理 CSI 与感知记录 |

## 数据关联设计

以业务样本标识为主键。优先使用现有 ROS 消息序号或业务数据 ID；如没有，再在应用层增加 sample_id。只有应用程序主动把一条样本切分成多个业务数据块时，才增加 chunk_id 和 chunk_count。

| 记录 | 建议字段 | 说明 |
|---|---|---|
| 感知样本 | sample_id、sensor_type、sensor_timestamp、data_type、data_size | 区分相机、雷达或其处理结果；先核实数据实际形态 |
| 位姿 | pose_timestamp、x、y、坐标系、pose_source | 来自实际使用的 odom、SLAM、TF 或经确认的外部定位 |
| 传输载荷 | sample_id、可选 chunk_id、发送时间、接收状态 | 受控 UDP 阶段将标识放入可从接收记录中识别的业务载荷 |
| CSI 记录 | CSI 时间戳、CSI 矩阵、RSSI、信道、带宽、速率及工具可提供的元数据 | 以采集工具实际输出字段为准，保留包与样本关联依据 |

关联规则：

1. 一个 sample_id 可对应零条、一条或多条有效 CSI 记录；丢包、重传、帧聚合和采集条件都会影响记录数量。
2. 首轮先用受控的小型 UDP 载荷验证样本标识能否从接收侧记录中恢复，并确认该记录同时具有有效 CSI。
3. CSI 硬件时间戳、Jetson 系统时间、ROS 时间和服务器时间可能不在同一时钟基准。以样本标识和载荷证据建立主关联；完成时钟偏移测量或同步后，再用时间差作校验。
4. 坐标应关联到传感器样本的采集时刻，并记录坐标系和来源。CSI 本身不提供位置。

## 分阶段实验与验收

| 阶段 | 工作内容 | 通过条件 |
|---|---|---|
| 0. 设备与路径核验 | 记录 TX/RX 型号、硬件版本、芯片、驱动、固件、接口；查清机器狗上行路径、定位来源和设备操作权限 | 兼容性、测量链路和可操作范围有明确结论；不兼容或信息不全时暂停刷写 |
| 1. CSI 基线 | 不接机器狗传感器；按项目支持的模式建立 TX/RX 无线链路，先确认关联和接口，再发受控小流量 | 接收端得到可解析且 CSI 长度非零的记录，并保存时间和工具提供的元数据 |
| 2. 业务标识关联 | 发送包含固定标记、sample_id、sensor_type 和发送时间的受控 UDP 载荷；检查接收侧是否能识别载荷及 CSI | 至少一批记录可把载荷标识与对应 CSI 建立可复核关联；数量差异有记录，不要求发送数与 CSI 数相等 |
| 3. 机器狗数据路径 | 先发送小型测试数据，确认其确实由目标 TX 无线接口发出并经空口到达 RX；并行检查服务器接收和 CSI 记录 | 数据交付路径与 CSI 采集链路一致；不能仅凭网络连通或以太网抓包判断 CSI 已采到 |
| 4. 位姿与单类感知数据 | 明确一种实际数据类型及其 ROS/业务序号；接入位姿来源，先单独验证相机或雷达一路 | 样本 ID、采集时间、位置和一组或多组 CSI 的匹配方法可复现，缺失和未匹配记录可统计 |
| 5. 多位置与并发扩展 | 前述链路稳定后，在可重复的位置和条件下采集；再逐步加入另一类传感数据 | 每轮保留设备配置、位置、样本数、有效 CSI 数、丢失/未匹配数和环境条件，结果可比较 |

首轮最小成功标准是阶段 1 和阶段 2：确认目标无线链路能产生有效 CSI，并证明测试载荷中的业务标识可与 CSI 记录关联。未达到这两个条件前，不进入相机、雷达并发或移动场景测试。

## 环境与操作准备

设备型号和固件未知时，只进行资料阅读、设备清单整理、数据格式设计和本机离线解析准备。真实 CSI 必须由兼容无线硬件及其驱动产生；普通 Windows、Docker 或 WSL 虚拟网络不替代无线网卡的 CSI 能力。

进入实验室后，优先检查现有固件和采集程序能否工作。任何固件编译、升级或刷写前，先确认设备所有者许可、完整型号与硬件版本、匹配镜像、备份及恢复方案。型号不清、镜像不匹配、设备承担其他用途或没有恢复方案时停止该操作。

电脑通过网线连接路由器管理时，应根据现场已有网络配置选择管理地址和端口；不要默认地址、接口名或信道一定与教程示例相同。TX 与 RX 的管理网络应避免地址冲突；管理线不得构成绕过被测 Wi-Fi 的业务通路。

## 待实验室确认

- 可用于 TX 和 RX 的设备完整型号、硬件版本、无线芯片、驱动及当前 CSI 固件/工具版本。
- 机器狗上行数据当前经过的无线设备和接收端；实验目标是测原生无线链路，还是允许新增外置 CSI 链路。
- 视觉和雷达侧实际传输的是原始数据、压缩数据、特征还是处理结果；现有消息序号或业务 ID 是否可用。
- 位姿的权威来源、坐标系、时间戳及与传感器消息的对应方式。
- 设备操作、固件修改、数据保存和实验场地的权限与恢复安排。
