# 现场网络与时空接口预检

## 目标

建立机器狗在时刻 t、位置 (x,y) 上传真实雷达与视觉样本时，其应用包、实际无线帧和接收端 CSI 的可核查关联。位置与传感器时钟、采集时间和无线传输时间各自有来源和误差，不能仅凭同一采集窗口认定同步。

## 现场预检

- 已通过既有 SSH 主机密钥与系统架构确认机器狗 Jetson；Windows 与 Ubuntu 工作站有线管理链路可用。
- 工作站独立 AX210 与 Jetson 连接同一 5 GHz 热点，双方双向 ping 2/2；板载 Wi-Fi 使用另一网络。Windows 的 Wi-Fi 接收端实际收到 Jetson 发来的一个 8 字节 UDP 测试包。该测试不能代替完整业务吞吐和 CSI 关联验证。
- Go2 三个 DDS 状态主题在 5 秒内分别收到 2510、2504、100 次回调，全部解析成功；取得位置和原始 stamp。抽查一条位置 stamp 与 Jetson 接收系统时间相差约 168.27 秒；时钟域尚未核实，不能将差值解释为延迟或直接做跨时钟匹配。位置坐标系、单位和原点仍需确认。
- 相机服务正在运行，但当前缓存 JPEG 接口不输出帧采集时间、帧号或 frameset ID。HTTP 请求时间不等于曝光时间；RGB 和深度分别读取缓存也不能保证是同一帧对。系统提示磁盘服务配置与当前加载的配置不同；本轮未重启或修改服务。

## 边界和下一步

此次只验证网络、状态与接口，没有启动 CSI 采集或上传真实传感器样本，也没有移动机器狗。监听会使当前负责 CSI 的独立 AX210 退出 Wi-Fi 业务连接；下一步应在保留有线管理的前提下验证独立业务接收路径，准备捕获对应会话的无线帧，并按需要由用户手动重连 Jetson。需要保存并验证相机采集时间和帧标识、雷达数据采集时钟、位置时间与坐标系，再将分片 ID 与 CSI record 按帧字节关联。原始数据和网络身份仅保留本地。
