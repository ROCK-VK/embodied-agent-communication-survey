# 8d-a 单次重关联尝试结果

日期：2026-10-21。本文仅发布匿名计数与验证边界；原始串流、逐帧数据、设备标识和网络标识保留在本地。

## 结果

本轮使用 sniffer-8d-a-full-filter 固件，在 ESP32-C5 的 HANDSHAKE_ONLY 模式和 channel 2 上被动采集约239秒。采集正常结束并收到 FINAL，停止原因是 duration_limit。

本模式只统计 CSI callback 和 handshake 诊断项，不导出 CSI_DATA 原子记录；因此这些计数只能证明本轮 CSI 回调持续运行，不能证明有可关联的 CSI 样本或握手帧。

## 重关联尝试

用户明确授权后，本轮仅发出一次远程 reassociate 命令。远程命令返回 exit code 1，没有得到成功确认。随后约18秒的 SSH 端口观察为44/44可达；这段观察短于预定的30秒上限。命令是否触发过短暂无线状态变化无法确认，现场没有观察到 SSH 中断，也没有捕获 EAPOL。后续有限的只读状态检查仍显示 Jetson 在 channel 2。

因此，本轮不能算作一次已确认的断网重连；M1–M4 均未捕获。退出码本身不足以确定失败原因，本报告不推断是 sudo、wpa_cli 还是无线状态导致。

ESP 采集最终因设定时长结束，MODE STOP / FINAL 正常，RF 已关闭。没有发生自动第二次重连，也没有进入 PROBE、发送业务 UDP 或做 WPA2 解密。

## 判断与下一步

- 8d-a full filter 在本轮持续收到有效目标 CSI，且队列、串口、截断和堆内存指标均未触发资源异常。
- 本轮没有足够证据判断重关联是否实际生效，也没有完整握手结果。
- 用户提出下一轮手动断开并恢复 Jetson Wi-Fi。执行前需先重新启动 ESP HANDSHAKE_ONLY，检查 CSI、ESP 与 SSH 状态；确认采集就绪后再由用户手动断开、并在得到用户通知后手动恢复连接。
- 只允许一个手动断开/恢复周期。采集结束或异常时停止，不自动重试。
- 完整 M1–M4 经离线解析确认前，不进入 PROBE、UDP 或 WPA2 解密。

本轮未修改 Jetson、AP、路由、驱动、ROS 或服务；没有发送 UDP、运动命令或 LiDAR 数据。
